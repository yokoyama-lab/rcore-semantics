# difftest: the gap witnesses on two older R-CORE interpreters

This directory runs the witnesses of `proofs.v` Sect. 41A/41B (the
assignment gap, the loop guards) and Sect. 41B''' (which store `E` is read
in) through two independent R-CORE interpreters that predate the paper's
semantics, and through the interpreter extracted from `proofs.v`.
The one-page result is `docs/gap-witness-table.md`.

* [tetsuo-jp/rcore-haskell](https://github.com/tetsuo-jp/rcore-haskell)
  (2015, master @ a31d05f): `src/RCore/Eval.hs`.
* [tetsuo-jp/rcore-C-ocaml](https://github.com/tetsuo-jp/rcore-C-ocaml)
  (2016, master @ be3c27f): `web/src/EvalRcore.ml`, CLI `ri`.

## Building the two interpreters (what worked here, 2026-09-23)

Ubuntu 24.04 (noble), everything from the distribution archive:

```sh
apt-get install -y ghc cabal-install ocaml ocaml-findlib bnfc
#  ghc 9.4.7, cabal-install 3.8.1.0, ocaml 4.14.1, ocamlfind 1.9.6, bnfc 2.9.5
```

### rcore-haskell

The cabal file pins `base < 4.9` (GHC 7.10), so bypass cabal and call ghc
directly, as the repository's own `src/Makefile` does.  With GHC >= 8.4
`Prelude` exports `(<>)`, which clashes with `Text.PrettyPrint.(<>)` in
three modules; `patches/rcore-haskell-ghc94.patch` adds
`import Prelude hiding ((<>))` to each (no semantic change).

```sh
git clone https://github.com/tetsuo-jp/rcore-haskell && cd rcore-haskell
git apply /path/to/rcore-semantics/difftest/patches/rcore-haskell-ghc94.patch
cd src && ghc --make Main.hs -o rcore-haskell
./rcore-haskell ../examples/reverse.rcore ../examples/list123_atom.rwhile
#  ('3.('2.('1.nil)))
```

CLI: `rcore-haskell [-t SECONDS] prog.rcore value-file` (default timeout
1 s, exit 124 on timeout).  There is no inversion flag: `RCore.Invert` is
not imported by `Main.hs`.  The parser (`RCore/Parser.hs`) accepts only
`X<digit>` variables and flat expressions, and does not skip a comment
that precedes `read` (so the witness files put their comment after the
`read` line).

### rcore-C-ocaml

The parser is generated by BNFC.  `Rcore.cf` contains UTF-8 characters,
which bnfc 2.9.5 refuses to read under the C locale; run make in a UTF-8
locale.  No source change was needed.

```sh
git clone https://github.com/tetsuo-jp/rcore-C-ocaml && cd rcore-C-ocaml/web/src
LC_ALL=C.UTF-8 make            # bnfc -ocaml, ocamlyacc, ocamllex, ocamlfind ocamlopt -o ri
./ri ../../examples/reverse.rcore ../../examples/list_abc.rcore_val
#  ('c . ('b . ('a . nil)))
```

CLI: `ri [-inverse] [-p2d] [-exp] prog.rcore [value-file]`; with one
argument and `-inverse` it prints the inverted program.  (The Makefile's
`test` target refers to `../examples`, which is `../../examples` relative
to `web/src`.)

## Running the witnesses

```sh
difftest/run_witnesses.sh /path/to/rcore-haskell/src/rcore-haskell /path/to/rcore-C-ocaml/web/src/ri
```

prints, for each program in `witnesses/`, both interpreters' output and
exit code verbatim, then the inverse programs as printed by `ri -inverse`.
The programs use only `X0..X9`, flat expressions and values over `nil`,
which both dialects accept byte-for-byte, so one file per witness serves
both interpreters (the `_hs`/`_ml` suffix is used only for the two
repositories' own `reverse.rcore` controls, which differ by a comment).

| file | proofs.v | what it exercises |
|---|---|---|
| `gapwitness1.rcore` + `nil.val` | `gap_witness`, l.3762-3785 | `X0 ^= nil` at `nil_store` |
| `gapwitness2.rcore` + `nil.val` | `gap_witness2`, l.3786-3800 | `X0 ^= =? X1 X2` at `neq_store`, built by `X2 ^= =? X3 X4` |
| `gapwitness2_inv.rcore` + `t.val` | inverse of the above | |
| `oddloop.rcore` + `nil.val` | `odd_store`, l.3851-3885 | `from X0 loop X5 ^= nil until X1` at `odd_store`, built as in `odd_store_reachable` l.3860 |
| `oddloop_inv.rcore` + `oddval.val` | inverse of the above | exit guard on a value that is neither `t` nor `nil` |
| `loop_t.rcore` + `nil.val` | control | the same loop with `X0 = t` exactly |
| `selfassign.rcore`, `selfassign_inv.rcore` + `nil.val` | constructed here; cf. l.4213-4235, l.4380 | `X0 ^= X0` (not well-formed): which store `E` is read in |
| `mismatchclear.rcore` + `nil.val` | constructed here; cf. `odot` l.214, `PD_Asn` l.4070 | `X0 ^= nil` with `X0 = t`: outside the printed side condition |
| `reverse_hs.rcore`, `reverse_ml.rcore` + `list123_atom.val`, `list_abc.val`, `list_niltrees.val` | control | the two repositories' shared example |

Each witness program builds its initial store from the all-nil store by
well-formed assignments, reads its input into an otherwise unused
variable, and clears its scaffolding before `write`, because both old
interpreters require every variable other than the output to be `nil` at
the end (`Eval.hs` l.87, `EvalRcore.ml` l.114).

## The extracted interpreter

`witness_driver.ml` runs the same witnesses through `rcore_interp.ml`
(`make extract`) with `wf_cmd_dec`, `eval_cmd_fuel` and iterated
`step_fun`, and checks each against the outcome `proofs.v` proves.

```sh
make witness-test        # = make extract; ocamlc ... difftest/witness_driver.ml; ./witness_driver
```

CI runs it after `make extract-test` (`.github/workflows/build.yml`).
It was also executed here against the real extraction with Rocq 9.1.1
built from source (`rocq c` 23 s for proofs.v; `make check`, `make audit`,
`make correspondence`, `make extract-test` and `make witness-test` all pass;
transcript in the table's notes).
